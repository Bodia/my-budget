- **Jira Issue**: SCRUM-23 (Інтеграція Monobank Personal API: імпорт виписок за персональним токеном з чергою запитів та дедуплікацією)

---

## 1. Контекст та мета

Наразі імпорт фінансових даних у **My Budget** підтримує завантаження файлів (.xlsx, .csv) з Monobank, Моно Бюджет та Toshl Finance.
Мета цієї фічі — забезпечити пряму інтеграцію з **Monobank Personal API** за персональним токеном клієнта (отриманим на [api.monobank.ua](https://api.monobank.ua/)), що дозволяє:
1. Автоматично завантажувати транзакції без ручного експорту/імпорту файлів.
2. Дотримуватися суворого рейт-ліміту Monobank API (1 запит на 60 секунд) без помилок 429 завдяки реактивній черзі з таймером.
3. Отримувати та оновлювати актуальні баланси й кредитні ліміти карток користувача.
4. Забезпечити захист персонального токена локальним шифруванням банківського рівня (AES-GCM 256-bit).

## 2. Архітектура безпеки та збереження токена (Security Architecture)

### 2.1 Локальне шифрування токена (Web Crypto API)
- Персональний токен (`X-Token`) **ніколи не зберігається у відкритому вигляді** в `localStorage` чи `IndexedDB`.
- Для збереження використовується нативний браузерний `crypto.subtle`:
  - **Алгоритм**: `AES-GCM` з 256-бітним ключем.
  - **Вектор ініціалізації (IV)**: унікальний 12-байтний випадковий вектор на кожен запис.
  - **Ключ шифрування**: створюється неекспортований криптографічний ключ (`extractable: false`), збережений в окремому сховищі `IndexedDB` або похідний ключ (через `PBKDF2`).
  - **Життєвий цикл у пам'яті**: розшифрований токен зберігається виключно в закритій області пам'яті під час виконання активної синхронізації та очищується після завершення.
- В інтерфейсі токен завжди маскується: `u2_oB••••••••9192`.
- Передбачено дію «Видалити токен», яка безповоротно стирає шифротекст і криптоключ.

### 2.2 Проксі-шар та захист від SSRF (CORS Proxy)
Оскільки `api.monobank.ua` не повертає заголовків CORS для веб-браузерів:
- **Локальне середовище розробки**: налаштування проксі у `vite.config.ts`:
  - Маршрут `/api/monobank/*` перенаправляється на `https://api.monobank.ua/personal/*`.
- **Продакшн (Vercel)**: мінімальна Serverless-функція `api/mono-proxy.ts`:
  - **Суворий Whitelist ендпоінтів**: дозволено проксіювати виключно запити до:
    - `/personal/client-info`
    - `/personal/statement/:account/:from/:to`
  - **SSRF захист**: блокування будь-яких зовнішніх чи приватних IP/доменів із поверненням статусу `403 Forbidden`.
  - **HTTP методи**: суворо тільки `GET`.
  - **Zero-Logging токена**: заголовок `X-Token` видаляється з серверних логів.

## 3. Компоненти та сервіси

### 3.1 Клієнт API (`src/services/monobank/monobankClient.ts`)
- `fetchClientInfo(token: string): Promise<MonobankClientInfo>`:
  - Отримує профіль користувача, перелік рахунків (`accounts`), IBAN, масковані PAN, типи карток (`black`, `white`, `fop` тощо) та баланси/ліміти в копійках.
- `fetchStatement(token: string, accountId: string, from: number, to: number): Promise<MonobankStatementItem[]>`:
  - Завантажує виписку за вказаний діапазон у секундах Unix.
  - Обробляє пагінацію (якщо відповідь містить максимальні 500 записів).
  - Інтерцептор помилок: при статусі `429 Too Many Requests` переводить чергу в режим кулдауну.

### 3.2 Менеджер черги та рейт-лімітів (`src/services/monobank/syncEngine.ts`)
- **Розбиття на чанки (Chunking)**:
  - Максимальний інтервал одного запиту Monobank — 31 доба (2 682 000 сек).
  - Обраний період (30 днів, 3 міс, 6 міс, 1 рік) розбивається на чанки по 30 днів.
  - **Пріоритет завантаження**: від найсвіжіших чанків до старіших (reverse chronological).
- **Керування паузою 60 секунд (Rate Limiter)**:
  - Перший запит виконується негайно (якщо минуло >60 с від попереднього виклику).
  - Між наступними запитами витримується пауза рівно 60 секунд.
  - Кожну секунду транслюється подія зворотного відліку в UI (`secondsRemaining`).
- **Стейт-машина черги**:
  - Стан: `idle` → `fetching_client` → `syncing` → `waiting_cooldown` → `completed` | `paused` | `error`.
  - Можливість користувача зупинити синхронізацію: усі отримані чанки гарантовано зберігаються в базі.

### 3.3 Адаптер конвертації та дедуплікації (`src/services/monobank/monobankApiAdapter.ts`)
- **Конвертація полів**:
  - `amount`: `monoTx.amount / 100` (Monobank повертає копійки; від'ємні — витрати, додатні — дохід).
  - `date`: `new Date(monoTx.time * 1000).toISOString().slice(0, 19)`.
  - `mcc`: мапується через існуючий `mapMccToCategory()`.
  - `description`: `monoTx.description` (з додаванням `monoTx.comment`, якщо наявний).
  - `id`: `mono_api_${monoTx.id}`.
  - `hash`: детерміністичний SHA-256 хеш (`computeTransactionHash`).
- **Збагачення (Intelligence Engine)**:
  - Пропуск через `enrichTransaction()` (визначення банок-накопичень, чистих назв мерчантів, ЗСУ-благодійності, податків ФОП).
- **Дедуплікація**:
  - Порівняння з існуючими транзакціями в IndexedDB за `id` та `hash`.

### 3.4 Оновлення моделі рахунків (`src/types/finance.ts` & `src/db/database.ts`)
- Розширення інтерфейсу `Account`:
  - `balance?: number`: актуальний залишок у валюті картки (UAH / USD / EUR).
  - `creditLimit?: number`: кредитний ліміт картки.
  - `monobankAccountId?: string`: ідентифікатор рахунку в системі Monobank.
  - `lastSyncedAt?: string`: ISO дата останньої синхронізації.

   - Перемикач вкладок угорі: `[📁 Завантаження файлу] | [⚡ Monobank API]`.

   - Статус підключення, кнопка «Оновити баланси карток» (миттєвий виклик `/client-info` за 1 с), кнопка «Видалити токен».
3. **Віджети карток (`CardsManager.tsx` / `CardBadge.tsx`)**:
